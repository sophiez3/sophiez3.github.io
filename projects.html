Gravity Assist N-Body Simulator

PythonSimulationNumerical IntegrationN-Body Dynamics

Engineered an interactive multi-body orbital dynamics simulator in Python using Web VPython to model the non-linear trajectories and gravity assists of the Voyager 1 and Voyager 2 grand tours alongside an open-ended planetary sandbox. To maintain physical realism across astronomical distances, I implemented a 4th-Order Runge-Kutta (RK4) numerical integrator that computes net vector gravitational accelerations across the Sun, all eight major planets, and the spacecraft at each sub-step. To resolve high-velocity close encounters without global computational lag, I developed an adaptive time-stepping architecture governed by planetary Hill spheres: when Voyager crosses a planet's gravitational sphere of influence, the integrator automatically scales down the time step and shifts the camera frame to the encounter body, preventing artificial energy drift and numerical divergence during periapsis passes. The platform features historical scenario initializations for outer-planet flybys, interactive ray-projected orbital ring snapping and launch vector sliders for arbitrary probe configurations, and real-time phase plotting of kinetic and potential energy to verify orbital energy exchange throughout hyperbolic gravitational assists.

Smart Kitchen

Full-StackAgentic AIReactFastAPI

Smart Kitchen is a full-stack project deployed locally for the 2026 NOVA generative AI hackathon. It tackles common restaurant pain points on delivery platforms like DoorDash: running out of ingredients mid-service, mixed-up orders at handoff, and business records scattered across invoices and sales reports. The app connects three views to one backend. A customer storefront automatically grays out dishes and marks them “Sold Out” the moment an ingredient runs short. A kitchen dashboard shows live ingredient levels, a real-time order feed, and an AI-assisted supplier-note parser. A mobile-styled driver portal lets drivers scan a unique QR code on each bag to verify pickup before confirming drop-off, so only fully verified deliveries count toward payout and performance metrics. When an order is placed, the system looks up each dish’s recipe, deducts ingredients inside a database transaction (which prevents two customers from buying the last portion at the same moment), and recalculates menu availability automatically. Through the OpenRouter API, LLM features turn free-text requests like “double cheese, hold the onions” into exact inventory changes and convert messy supplier delivery notes into structured stock entries. AI output is treated as untrusted input: it is validated and capped in code, backed by a rule-based fallback, and reviewed by a human before anything is saved. The project uses Python, FastAPI, Pydantic, SQLite/SQL, React (Vite), JavaScript, REST APIs, structured LLM outputs (JSON schema), QR generation and camera scanning, Git, and pytest (39 automated tests). I built it step by step while learning software engineering fundamentals, using an AI assistant as a tutor and pair programmer.

Housing Peer Tool

FastAPIPythonPandas / NumPyOpenRouter LLMSVG

Proposed solutions to financial institutions in using AI to address housing affordability for the 2026 PNC x 180DC Challenge. An AI agent will classify different neighborhoods into different types that are each assigned a targed solution. We accompanied our proposal with a web app tool using Pennsylvania as a case study. The tool currently has example neighborhood data for Pennsylvannia and Pittsburgh only. A bank uploads two datasets, one of cities and one of neighborhoods, and the tool first matches the chosen city to structurally similar peers on population, income, job mix, housing age, commute, broadband and homeownership. It then fits rent against income across those peers to measure how far the city’s rent diverges from what its incomes predict, and ranks the factors that differ most. Inside the city, each neighborhood receives a 0–1 score for four archetypes (vacant sites, transit-adjacent lots, tangled titles and small-landlord rentals, and high energy burden), using threshold-based, explainable weights. Each neighborhood is also compared with similar peer neighborhoods to expose any unequal access among comparable areas. Each assigned type is routed to a specific bank product with partners and KPIs, with human and fair-lending review built into the workflow. The backend is a FastAPI service using pandas and NumPy for the analysis, with CSV validation and an in-memory dataset store. The frontend is a dependency-free single-page app with an SVG chart. An OpenRouter-connected language model turns the computed results into a recommendation memo, using only the calculated facts as input.

India CareFinder

DatabricksPySparkSpark SQLOpenStreetMapPython

Built for the Databricks Datathon 2026, India Carefinder is a web app that helps patients across India find reliable hospitals for urgent or planned medical procedures. While I used generative AI to help write the SQL, Python, and frontend code faster, the core product ideas and data logic came from my own planning: I figured out which hospital readiness factors mattered most, decided to weight them differently depending on whether a patient's need was an emergency or planned, brought in an outside OpenStreetMap dataset to double-check the provided hospital locations and details, and designed the app's "How We Decide" tab so users can see the exact reasons behind every recommendation. Behind the scenes, I built a Databricks pipeline using PySpark and Spark SQL that cleans the raw hospital data, checks coordinates against Indian PIN codes and OpenStreetMap records to catch location errors, pulls supporting quotes straight from hospital descriptions, and powers the live web app through a Databricks SQL Warehouse.
